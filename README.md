# Параллельное программирование. Лабораторные работы

Репозиторий содержит лабораторные работы по параллельному программированию.  
Исходные задания взяты из методички по **OpenMP** и адаптированы под язык программирования **Go**.

В методичке задачи сформулированы для OpenMP и языков C/C++ или Fortran.  
В данном репозитории аналогичное поведение реализуется стандартными средствами Go:

- потоки из заданий моделируются горутинами;
- параллельные области реализуются через горутины и `sync.WaitGroup`;
- критические секции реализуются через `sync.Mutex`;
- атомарные операции реализуются через `sync/atomic`;
- распределение итераций цикла между потоками реализуется вручную;
- функциональная декомпозиция реализуется через параллельные горутины с разными функциями;
- готовые библиотечные функции, решающие задачу целиком, не используются.

---

## Общая информация

Требования к выполнению работ:

1. Работа выполняется индивидуально.
2. Язык программирования — **Go**.
3. Запрещается использовать библиотечные функции, реализующие целиком решаемую задачу.
4. Число потоков и размер задачи передаются программе через командную строку (в версиях для онлайн-компилятора параметры задаются внутри кода).
5. Все лабораторные размещаются в одном репозитории в папках `lab1`, `lab2`, `lab3`, `lab4`.
6. Каждая работа содержит код и файл `README` с командами сборки и запуска.
7. По ходу выполнения делаются скриншоты вывода программы: команды запуска и полный вывод программы.

### Задача 5

Суть задачи:

> Напишите программу, которая читает из файла координаты точек в 3D пространстве (x, y, z) и вычисляет геометрический центр, который есть среднее по x, y и z. Напишите две версии программы: одну с распараллеливанием цикла, другую с функциональной декомпозицией.

Реализованы две версии:

| Режим | Описание | Аналог в OpenMP |
|---|---|---|
| `loop` | Декомпозиция по данным: точки делятся на блоки между потоками | `#pragma omp parallel for reduction` |
| `func` | Декомпозиция по функциям: три горутины (sumX, sumY, sumZ) | `#pragma omp parallel sections` |
| `both` | Обе версии подряд и сравнение результатов | — |

Программа читает точки из текстового файла. Для подготовки файла встроен генератор точек (команда `gen`).

Формат файла: каждая строка содержит `x y z`.

Запуск:

```bash

```

```bash

```

Версия с распараллеливанием цикла:

```bash
go run . 8 2000000 loop points.txt
```

Версия с функциональной декомпозицией:

```bash
go run . 8 2000000 func points.txt
```

Сравнение обеих версий:

```bash
go run . 8 2000000 both points.txt
```

### Задача 6

Суть задачи:

> Используя функциональную декомпозицию перепишите задачу 5 для вычисления значения по формуле: (Σx + Σy + Σz) / (3N), где N – количество точек. Используйте глобальную сумму и критические секции.

Ключевое отличие от задачи 5: все три функции (sumX, sumY, sumZ) добавляют свои частичные суммы в **одну общую глобальную переменную**, защищённую критической секцией (мьютексом `sync.Mutex`).

Аналог в OpenMP:

```c
#pragma omp parallel sections
{
    #pragma omp section
    {
        double sx = calc_sum_x();
        #pragma omp critical
        global_sum += sx;
    }
    // ... аналогично для sy и sz
}
```

Запуск:

```bash
cd lab4
```

Генерация файла:

```bash
go run . gen 2000000 points.txt
```

Вычисление:

```bash
go run . 8 2000000 points.txt
```

## Соответствие конструкций OpenMP и реализации в Go

| Конструкция OpenMP | Аналог в Go |
|---|---|
| `#pragma omp parallel` | запуск группы горутин |
| `omp_get_thread_num()` | параметр `id`, передаваемый в горутину |
| `omp_get_num_threads()` | количество запущенных горутин |
| `#pragma omp for` | ручное распределение итераций между горутинами |
| `schedule(static)` | статическое разбиение диапазона итераций |
| `schedule(dynamic)` | общая очередь блоков с защитой через `sync.Mutex` |
| `schedule(guided)` | динамическая выдача блоков с уменьшающимся размером |
| `#pragma omp critical` | `sync.Mutex` |
| `#pragma omp atomic` | операции из пакета `sync/atomic` |
| `#pragma omp barrier` | `sync.WaitGroup` |
| `#pragma omp sections` | параллельные горутины с разными функциями |
| `#pragma omp ordered` | каналы, условные переменные или другие механизмы упорядочивания |
| `reduction(...)` | ручная редукция через мьютексы, каналы или локальные аккумуляторы |
| `OMP_NUM_THREADS` | переменная `numThreads` в коде или аргумент командной строки |
| `OMP_SCHEDULE` | переменные `schedule` и `chunk` в коде |

## Проверка корректности

Во всех задачах, где выполняется вычислительная работа, предусмотрена проверка результата:

- в задаче 2 проверяется контрольная сумма результата (ожидаемая сумма для `a[i] = i` равна `N·(N-1)/2`);
- в задаче 4 проверяется совпадение контрольных сумм последовательной и параллельной версий;
- в задаче 3 проверяется строго обратный порядок вывода потоков;
- в задаче 5 проверяется совпадение геометрических центров двух версий и ожидаемого аналитического значения;
- в задаче 6 проверяется совпадение результата с ожидаемым аналитическим значением `N-1`.

Если программа выводит `OK: true`, `Results Match: true`, `Centers match: true` или `Match: true`, значит результат корректен.
