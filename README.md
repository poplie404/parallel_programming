# Параллельное программирование. Лабораторные работы

Репозиторий содержит лабораторные работы по параллельному программированию.  
Исходные задания взяты из методички по **OpenMP** и адаптированы под язык программирования **Go**.

В методичке задачи сформулированы для OpenMP и языков C/C++ или Fortran.  
В данном репозитории аналогичное поведение реализуется стандартными средствами Go:

- потоки из заданий моделируются горутинами;
- параллельные области реализуются через горутины и `sync.WaitGroup`;
- критические секции реализуются через `sync.Mutex`;
- атомарные операции реализуются через `sync/atomic`;
- распределение итераций цикла между потоками реализуются вручную;
- готовые библиотечные функции, решающие задачу целиком, не используются.

---

## Общая информация

Требования к выполнению работ:

1. Работа выполняется индивидуально.
2. Язык программирования — **Go**.
3. Запрещается использовать библиотечные функции, реализующие целиком решаемую задачу.
4. Число потоков и размер задачи передаются программе через командную строку.
5. Все лабораторные размещаются в одном репозитории в папках `lab1`, `lab2`, `lab3`, `lab4`.
6. Каждая работа содержит код и файл `README` с командами сборки и запуска.
7. По ходу выполнения делаются скриншоты вывода программы: команды запуска и полный вывод программы.

## Лабораторная работа 1

Папка:

```text
lab1/
```

Первая лабораторная содержит задачи 1, 2 и 3 из методички.

### Задача 1

Папка:

```text
lab1/task1
```

Суть задачи:

> Написать программу, где каждый поток печатает свой идентификатор, количество потоков всего и строчку `Hello World`. Запустить программу с 8 потоками. Всегда ли вывод идентичен? Почему?

Запуск:

```bash
cd lab1/task1
go run . 8
```

или:

```bash
cd lab1/task1
go run . 8 1
```

Второй аргумент поддерживается для единообразия, но в первой задаче размер задачи не влияет на логику.

---

### Задача 2

Папка:

```text
lab1/task2
```

Суть задачи:

> Написать программу, в которой объявлен массив из 16000 элементов и инициализирован так, что значение элемента массива равно его порядковому номеру. Затем создайте результирующий массив, в котором, за исключением крайних элементов, будут средние значения исходного массива:
>
> ```text
> b[i] = (a[i-1] + a[i] + a[i+1]) / 3.0
> ```
>
> Запустите программу с 8 потоками при различных типах распределения работ.

Примеры запусков:

```bash
cd lab1/task2

go run . 8 16000 static
go run . 8 16000 static 1000
go run . 8 16000 dynamic 100
go run . 8 16000 guided 100
```

Для режима `runtime`:

```bash
LAB2_SCHEDULE=dynamic,100 go run . 8 16000 runtime
```

или через `OMP_SCHEDULE`:

```bash
OMP_SCHEDULE=guided,200 go run . 8 16000 runtime
```

---

### Задача 3

Папка:

```text
lab1/task3
```

Суть задачи:

> Модифицируйте задачу 1 так, чтобы потоки распечатывали свои идентификаторы в обратном порядке. Существует как минимум 5 способов решения. Постарайтесь найти как можно больше.

В реализации представлены 5 способов:

1. `mutex` — активное ожидание через атомарный счетчик;
2. `cond` — пассивное ожидание через `sync.Cond`;
3. `chan_chain` — цепочка каналов, передача эстафеты от старшего потока к младшему;
4. `chan_array` — координатор и массив каналов с подтверждением завершения;
5. `wg_chain` — цепочка на основе `sync.WaitGroup`.

Запуск всех способов:

```bash
cd lab1/task3
go run . 8 1000
```

Запуск конкретного способа:

```bash
go run . 8 1000 mutex
go run . 8 1000 cond
go run . 8 1000 chan_chain
go run . 8 1000 chan_array
go run . 8 1000 wg_chain
```

## Лабораторная работа 2

Папка:

```text
lab2/
```

### Задача 4

Суть задачи:

> Напишите программу перемножения больших матриц. Сравните время выполнения последовательной и параллельной программы на 2, 4, 8 потоках.

В программе реализованы:

- последовательное умножение матриц;
- параллельное умножение матриц;
- проверка корректности результата через контрольную сумму;
- замер времени выполнения;
- расчет ускорения, то есть `speedup`.

Матрицы хранятся в одномерных срезах для более эффективной работы с памятью.  
Используется порядок циклов `i -> k -> j`, который уменьшает количество промахов кэша по сравнению с наивным порядком `i -> j -> k`.

Запуск:

```bash
cd lab2
```

Сравнение времени на разном числе потоков:

```bash
go run . 2 1000
go run . 4 1000
go run . 8 1000
```

Также можно запустить с одним потоком для базового сравнения:

```bash
go run . 1 1000
```

Формат аргументов:

```text
<число_потоков> <размер_матрицы>
```

Например:

```bash
go run . 8 1000
```

означает:

- `8` — количество потоков;
- `1000` — размер матрицы, то есть умножаются матрицы `1000 x 1000`.

## Соответствие конструкций OpenMP и реализации в Go

| Конструкция OpenMP | Аналог в Go |
|---|---|
| `#pragma omp parallel` | запуск группы горутин |
| `omp_get_thread_num()` | параметр `id`, передаваемый в горутину |
| `omp_get_num_threads()` | количество запущенных горутин, обычно аргумент командной строки |
| `#pragma omp for` | ручное распределение итераций между горутинами |
| `schedule(static)` | статическое разбиение диапазона итераций |
| `schedule(dynamic)` | общая очередь блоков с защитой через `sync.Mutex` |
| `schedule(guided)` | динамическая выдача блоков с уменьшающимся размером |
| `#pragma omp critical` | `sync.Mutex` |
| `#pragma omp atomic` | операции из пакета `sync/atomic` |
| `#pragma omp barrier` | `sync.WaitGroup` |
| `#pragma omp ordered` | каналы, условные переменные или другие механизмы упорядочивания |
| `reduction(...)` | ручная редукция через мьютексы, каналы или локальные аккумуляторы |

## Проверка корректности

Во всех задачах, где выполняется вычислительная работа, предусмотрена проверка результата:

- в задаче 2 проверяется контрольная сумма результата;
- в задаче 4 проверяется совпадение контрольных сумм последовательной и параллельной версий;
- в задаче 3 проверяется строго обратный порядок вывода потоков.

Если программа выводит `OK: true` или `Results Match: true`, значит результат корректен.

## Примечание

Так как исходная методичка описывает OpenMP, в коде на Go нет директив `#pragma omp`.  
Все соответствующие конструкции реализованы вручную средствами языка Go.

Например:

```go
var wg sync.WaitGroup
```

используется как аналог барьера в конце параллельной области.

```go
var mu sync.Mutex
```

используется как аналог критической секции.

```go
runtime.GOMAXPROCS(numThreads)
```

используется для ограничения количества потоков процессора, доступных программе.
