# Лабораторная работа 1. Задача 3

## Условие задачи из методички

Модифицируйте задачу 1 так, чтобы потоки распечатывали свои идентификаторы в обратном порядке. Существует как минимум 5 способов решения. Постарайтесь найти как можно больше.

## Реализация на Go

В параллельном программировании порядок выполнения потоков по умолчанию недетерминирован. Чтобы заставить потоки печатать свои идентификаторы строго в обратном порядке (от `N-1` до `0`), необходимо использовать примитивы синхронизации.

В данной работе реализовано **5 различных способов** решения задачи:

1. **Atomic Spinlock (Активное ожидание)**
   Используется атомарный счетчик `atomic.Int32`. Каждый поток в цикле проверяет, не наступила ли его очередь. Если нет — он отдает квант времени планировщику (`runtime.Gosched()`).
   *Плюсы:* Простота. *Минусы:* Холостой расход процессорного времени (busy-wait).

2. **sync.Cond (Условная переменная / Пассивное ожидание)**
   Потоки захватывают мьютекс и "засыпают" (`cond.Wait()`), если очередь еще не подошла. Когда поток отработает, он будит остальных (`cond.Broadcast()`).
   *Плюсы:* Экономит ресурсы CPU, так как спящие потоки не потребляют такты процессора.

3. **Channel Chain (Цепочка каналов / Передача эстафеты)**
   Создается массив каналов. Поток `i` ждет сигнала от потока `i+1`. Последний поток (`N-1`) начинает работу сразу, печатает и отправляет сигнал потоку `N-2`, и так далее.
   *Плюсы:* Децентрализованная синхронизация, элегантное использование каналов Go.

4. **Channel Array (Массив каналов / Координатор)**
   Главный поток (координатор) создает массив каналов и в цикле отправляет разрешения на печать каждому потоку строго в обратном порядке.
   *Плюсы:* Жесткий централизованный контроль порядка выполнения.

5. **WaitGroup Chain (Цепочка WaitGroup)**
   Аналогично цепочке каналов, но используется примитив `sync.WaitGroup`. Поток `i` вызывает `Wait()` на `WaitGroup` потока `i+1`, ожидая его завершения.

*Примечание:* В коде присутствует фиктивная функция `doWork(taskSize)`, чтобы формально использовать параметр `task_size`, передаваемый через командную строку, как того требуют общие правила оформления лабораторных работ.

## Сборка и запуск

Перейти в папку лабораторной:

```bash
cd lab1/task3
```

### Запуск всех 5 методов подряд

```bash
go run . 8 1000
```
*(8 потоков, размер задачи 1000)*

### Запуск конкретного метода

Вы можете передать название метода третьим аргументом:

```bash
go run . 8 1000 mutex
go run . 8 1000 cond
go run . 8 1000 chan_chain
go run . 8 1000 chan_array
go run . 8 1000 wg_chain
```
