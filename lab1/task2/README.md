# Лабораторная работа 1. Задача 2

## Условие задачи из методички

Написать программу, в которой объявлен массив из 16000 элементов и инициализирован так, что значение элемента массива равно его порядковому номеру. Затем создайте результирующий массив, в котором (за исключением крайних элементов) будут средние значения исходного массива:

```text
b[i] = (a[i-1] + a[i] + a[i+1]) / 3.0
```

Запустите программу с 8-ю процессами при различных типах распределения работ.

## Реализация на Go

В исходной методичке задача сформулирована для OpenMP. В данной работе тот же смысл реализован на языке Go.

В качестве аналога потоков используются горутины. Программа:

1. принимает количество потоков из командной строки;
2. принимает размер задачи из командной строки;
3. заполняет исходный массив `a` значениями, равными индексам элементов;
4. параллельно вычисляет массив `b`;
5. поддерживает разные типы распределения работ, аналогичные `schedule` из OpenMP;
6. печатает статистику распределения и контрольную сумму результата.

Формула для внутренних элементов:

```text
b[i] = (a[i-1] + a[i] + a[i+1]) / 3.0
```

Крайние элементы `b[0]` и `b[n-1]` в условии не определены. В данной реализации они копируются из исходного массива:

```text
b[0] = a[0]
b[n-1] = a[n-1]
```

## Поддерживаемые типы распределения работ

Программа поддерживает следующие значения `schedule`:

- `static`;
- `dynamic`;
- `guided`;
- `runtime`.

### static

Если `chunk` не задан или равен `0`, внутренняя область массива делится между потоками непрерывными блоками примерно равного размера.

Пример:

```bash
./task2 8 16000 static
```

Если `chunk` задан, блоки фиксированного размера раздаются потокам циклически.

Пример:

```bash
./task2 8 16000 static 1000
```

### dynamic

Каждый поток запрашивает следующий блок работы из общей очереди. Размер блока задается параметром `chunk`. Если `chunk` не задан, используется размер `1`.

Пример:

```bash
./task2 8 16000 dynamic
```

или с размером блока:

```bash
./task2 8 16000 dynamic 100
```

### guided

Аналог `dynamic`, но размер очередного блока уменьшается по мере обработки массива. Минимальный размер блока задается параметром `chunk`. Если `chunk` не задан, используется `1`.

Пример:

```bash
./task2 8 16000 guided
```

или:

```bash
./task2 8 16000 guided 100
```

### runtime

Тип распределения и размер блока можно задать через переменные окружения:

- `task2_SCHEDULE`;
- `OMP_SCHEDULE`.

Формат:

```text
schedule[,chunk]
```

Пример для Linux/macOS:

```bash
task2_SCHEDULE=dynamic,100 ./task2 8 16000 runtime
```

Пример с использованием `OMP_SCHEDULE`:

```bash
OMP_SCHEDULE=guided,200 ./task2 8 16000 runtime
```

## Сборка и запуск

### Linux / macOS

Перейти в папку лабораторной:

```bash
cd task2
```

Собрать программу:

```bash
go build -o task2 .
```

Запуск для задачи из методички, 8 потоков и 16000 элементов:

```bash
./task2 8 16000 static
./task2 8 16000 static 1000
./task2 8 16000 dynamic 100
./task2 8 16000 guided 100
```

Запуск с `runtime`:

```bash
task2_SCHEDULE=dynamic,100 ./task2 8 16000 runtime
```

или:

```bash
OMP_SCHEDULE=guided,200 ./task2 8 16000 runtime
```

Также можно запускать без предварительной сборки:

```bash
go run . 8 16000 static
go run . 8 16000 dynamic 100
```

### Windows PowerShell

Перейти в папку лабораторной:

```powershell
cd task2
```

Собрать программу:

```powershell
go build -o task2.exe .
```

Запуски:

```powershell
.\task2.exe 8 16000 static
.\task2.exe 8 16000 static 1000
.\task2.exe 8 16000 dynamic 100
.\task2.exe 8 16000 guided 100
```

Для `runtime`:

```powershell
$env:task2_SCHEDULE="dynamic,100"
.\task2.exe 8 16000 runtime
```

или:

```powershell
$env:OMP_SCHEDULE="guided,200"
.\task2.exe 8 16000 runtime
```

## Ответ на вопрос про распределение работ

Итоговый массив `b` и контрольная сумма не должны зависеть от типа распределения работ, потому что каждая итерация цикла обрабатывает разные индексы массива, и нет гонок по данным.

Однако статистика распределения работы между потоками и время выполнения могут отличаться, потому что разные типы расписания по-разному выдают потокам блоки итераций:

- `static` делит работу заранее;
- `dynamic` выдает работу по запросу;
- `guided` выдает большие блоки в начале и меньшие блоки в конце;
- `runtime` позволяет задать поведение через переменную окружения.
